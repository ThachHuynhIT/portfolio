# Non-home public pages — restyle design

Date: 2026-11-09. Status: ready for Claude review; implementation is a later step.

## Intent and authority

Bring `/photography`, `/photography/album/[slug]`, `/music`, `/projects`, `/blog`, `/blog/[slug]`, the 404 view and `/tools/json-validator` into the homepage's observatory visual system. This is a presentation change, with the explicitly authorized Grid/Masonry keyboard fix. Use the current homepage as the visual reference, not the historical pre-overhaul screenshots.

Sources read: all of `CLAUDE.md` (especially §§2, 4, 5), `docs/superpowers/specs/2026-11-06-portfolio-design-direction.md`, `docs/superpowers/plans/2026-11-06-portfolio-overhaul.md`, `docs/DESIGN_TOKENS.md`, and the source files identified below. The user's 2026-11-09 decisions supersede historical statements that other routes retain R3F stars. The 404 page keeps its black hole (it already matches the homepage); only its text/HUD is re-skinned. The old direction's prototype gate is already settled for this reuse; do not reopen it.

## Shared visual contract

Reuse `src/app/globals.css` and the live composition in `src/app/page.tsx` and `src/components/sections/{About,Skills,Projects,PhotoPreview,BlogPreview,Contact}Section.tsx`:

- `.portfolio-theme`: Be Vietnam Pro, falling back to Inter; already loaded with Vietnamese in `src/app/layout.tsx`. Do not add a font dependency or replace the root legacy font.
- `bg-portfolio-void`, `bg-portfolio-hull`, `text-portfolio-ink`, `text-portfolio-dust`, `text-portfolio-accretion`, `border-portfolio-hairline`, `border-portfolio-control`. These are complete literal Tailwind utilities, composed with `cn()` from `src/lib/utils.ts` when conditional.
- Dark tokens: Void `#05070D`, Hull `#0C1018`, Ink `#ECE9E4`, Dust `#9BA1AC`, Accretion `#F2B45A`, Accretion hover `#F7C579`, on-accretion `#05070D`, Hairline `rgba(236,233,228,0.12)`, Control `#747B89`. Light values already exist under `[data-theme="light"] .portfolio-theme`: Void `#F5F6F8`, Hull `#FFFFFF`, Ink `#10131A`, Dust `#4F5562`, Accretion `#9A5B0B`, hover `#804A08`, on-accretion `#FFFFFF`, Hairline `rgba(16,19,26,0.14)`, Control `#747B89`. Values belong in scoped CSS, not component literals.
- `.portfolio-section` provides `2rem 0 6rem` rhythm; `.portfolio-column` gives `min(1120px, calc(100% - 32px))`. Add navigation clearance once at page level. Reading content is limited to about 68ch within that column.
- `.portfolio-solid`: opaque Hull, Ink, Hairline border, 8px radius; `.portfolio-surface` must also be opaque Hull within the new page shell (today its explicit opaque override is only under `#portfolio-sections`). `.portfolio-case` and `.portfolio-case-title` provide restrained project hover/focus response. `.portfolio-reading` is a reading scrim, not a replacement for an opaque dense-content surface.
- `.portfolio-action` plus `.portfolio-action-primary` or `.portfolio-action-secondary`; `.portfolio-text-link`; `.portfolio-input`. Primary/secondary states reuse the homepage rules; do not invent extra glow/gradient treatments. Controls have visible Accretion focus and at least 44px icon targets. Disabled states remain visibly disabled with no hover response.
- Active filters/tabs use Accretion border/text on Hull (or primary Accretion fill with `--portfolio-on-accretion` where already button-like), plus their existing selected/pressed semantics. Inactive controls use Ink/Dust and Control borders; hover/focus changes the border to Accretion. Keep local control rows wrapping or internally scrolling without widening the viewport.
- `docs/DESIGN_TOKENS.md` also documents legacy `brand`, `surface`, `text`, and `presets` recipes. They often expand to purple/cyan, translucent surfaces or `light:` pairs. Do not treat importing those recipes as conversion; replace their visual use in scoped consumers, retaining harmless size/gap tokens.

## Scope and background ownership

`src/components/layout/GlobalBackground.tsx` currently dynamically imports `StarryBackground3D`, waits for `useTheme().isMounted`, returns a purple/cyan radial wash in light mode and R3F stars otherwise. `PortfolioScope` excludes every route in `isExcludedRoute()` from `.portfolio-theme`. `src/app/layout.tsx` places `GlobalBackground` before that scope and the global mini player after it.

Replace the R3F import/render with one noninteractive, `aria-hidden`, fixed CSS background: own `.portfolio-theme` scope, Void base, `.portfolio-stars` child, pointer-events none, behind content. Render for non-home public paths including unknown paths that resolve to 404; no mount gate, randomness, parallax, listeners or Canvas. The homepage returns null here and keeps `HomeBlackHole` and its stars unchanged. `/admin` and `/couple` return null using exact prefix-or-child boundaries; neither subtree is restyled. The formerly global R3F decoration ceases mounting there as part of its removal; do not add a couple background or edit its page/module.

Leave `PortfolioScope` excluding `/admin`, `/couple`, `/music`. Give `.music-page-root` its own `.portfolio-theme` and dark marker locally so the excluded navigation/footer do not accidentally acquire public styles. Background gets the same dark marker for music. Delete `src/components/3d/StarryBackground3D.tsx` only after repository import/export search proves it has no remaining consumers; keep `SceneContainer.tsx`, its barrel export and all black hole engine files.

Lightbox is not portalled; keep its current typography. Add the dark scope marker there solely to resolve Accretion safely on a light parent. Only purple/cyan/violet accent styling changes; theater black surfaces, image scrims, typography and interactions stay intact.

## Motion and rendering

One entrance moment per section, supplied by the header where present. No per-card reveal cascades. Use shared variants in `src/lib/animations.ts`, `initial={false}` for SSR visibility and `viewport={{ once: true }}`. For this restyle use transform/opacity only; do not use `blurFadeIn` or `clipReveal` just because they exist. Reduced motion displays the final state immediately, suppresses decorative spins/pulses/parallax and stills visualizers; playback and functional slider/seek behavior continue. Existing lightbox animation is specifically outside the restyle exception. Server-fed content and headings render with JS disabled; interactive controls naturally require hydration. Do not add a client fetch or mount guard to hide content. Existing client components may remain client; server pages stay server.

Keep SceneContainer and theater mode. No new pure logic helper is needed.

## Acceptance and delivery

All routes above use the shared visual contract, including empty/loading/error states that already exist. At 375px and 1440px there is no horizontal page overflow, text and controls remain readable, keyboard focus is visible, and Grid/Masonry open via Enter and Space. Verify dark/light for all public routes, with dark-only music/lightbox also checked while the surrounding stored preference is light. Measure text contrast at least 4.5:1 and control boundaries/focus at least 3:1 against actual surfaces. Smoke-test unchanged controls and language selection. Confirm no non-home R3F background mounts (the 404 black hole is intentionally kept); homepage remains unchanged.

Implementation uses existing `feature/pages-restyle` from `develop`, Codex UI work with Claude review and a commit per independently shippable phase. No merge without owner. Budget approximately 120 minutes including checks: shell 25, photography 30, music 35, remaining pages 30. Prefer direct token substitutions and reduced decoration over new abstractions/refactors. Checks are performed by Claude; this authoring step runs no npm/Node commands. Implementation documentation updates belong to Phase 1 (`CLAUDE.md`, `docs/ARCHITECTURE.md`), not this two-file-only authoring step.

## Risks

Music has many literals outside its token block and canvas cannot consume unresolved CSS `var()` strings. Background/negative stacking and the mini player's independent scope need route-transition checks. Shared heading changes must preserve homepage h2 appearance. Project image absence is real and must not become new placeholder art. DB-backed build needs configured environment; blocked checks must be reported, never claimed green. Scope must remain presentation-only despite tempting player/lightbox refactors.
